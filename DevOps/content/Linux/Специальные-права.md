# Специальные права доступа в Linux

Помимо стандартных прав `r`, `w` и `x`, в Linux существуют три специальных бита:

- **SUID** — выполнение программы с правами владельца;
- **SGID** — выполнение с правами группы или наследование группы каталогом;
- **Sticky bit** — защита чужих файлов от удаления в общем каталоге.

---

## SUID — Set User ID

### Что делает SUID

Если на исполняемом файле установлен **SUID**, программа запускается с правами **владельца файла**, а не пользователя, который её запустил.

Например, если владельцем программы является `root`, то при её запуске процесс временно получает эффективные права `root`.

> SUID имеет практический смысл преимущественно для исполняемых файлов. В Linux SUID на каталогах обычно игнорируется.

### Пример: `passwd`

Команда `passwd` позволяет обычному пользователю изменить свой пароль.

При этом информация о паролях хранится в защищённом файле:

```text
/etc/shadow
```

Обычный пользователь не может напрямую изменять этот файл. Однако владельцем программы `passwd` является `root`, а на самой программе установлен SUID.

Проверить это можно командой:

```bash
ls -l "$(command -v passwd)"
```

Пример результата:

```text
-rwsr-xr-x 1 root root ... /usr/bin/passwd
```

Буква `s` на месте права выполнения владельца означает, что установлен SUID:

```text
rws
  ↑
 SUID
```

### Установка SUID

Символический способ:

```bash
chmod u+s file
```

Числовой способ:

```bash
chmod 4755 file
```

Число `4` в старшем разряде обозначает SUID:

```text
4755
│└── стандартные права rwxr-xr-x
└─── SUID
```

Удаление SUID:

```bash
chmod u-s file
```

### Риск безопасности

Особенно опасны SUID-программы, владельцем которых является `root`.

Если такая программа содержит уязвимость, злоумышленник потенциально сможет выполнить действия с привилегиями `root`.

Поэтому:

- SUID следует назначать только при необходимости;
- программа должна быть защищена от изменения обычными пользователями;
- SUID нельзя бездумно устанавливать на пользовательские программы и интерпретаторы;
- SUID на shell-скриптах в современных Linux обычно игнорируется из соображений безопасности.

Найти SUID-файлы в системе можно командой:

```bash
find / -type f -perm -4000 2>/dev/null
```

## SGID — Set Group ID

Поведение SGID зависит от того, установлен он на **исполняемом файле** или на **каталоге**.

### SGID на исполняемом файле

Если SGID установлен на программе, при запуске процесс получает эффективные права **группы-владельца файла**, а не основной группы пользователя.

Установка SGID:

```bash
chmod g+s file
```

Числовой способ:

```bash
chmod 2755 file
```

В выводе `ls -l` SGID обозначается буквой `s` на месте права выполнения группы:

```text
-rwxr-sr-x
      ↑
     SGID
```

Удаление SGID:

```bash
chmod g-s file
```

### SGID на каталоге

SGID особенно часто используется для общих каталогов.

Если каталог имеет SGID, новые файлы и подкаталоги внутри него наследуют **группу этого каталога**, а не основную группу пользователя, который их создал.

Это удобно при совместной работе над проектом.

### Пример настройки общего каталога

Создадим каталог и назначим ему группу:

```bash
mkdir mysharedfolder
chgrp developers mysharedfolder
```

Предоставим владельцу и группе полные права:

```bash
chmod 775 mysharedfolder
```

Установим SGID:

```bash
chmod g+s mysharedfolder
```

То же самое одной командой в числовом формате:

```bash
chmod 2775 mysharedfolder
```

Проверяем:

```bash
ls -ld mysharedfolder
```

Результат будет выглядеть примерно так:

```text
drwxrwsr-x 2 user developers ... mysharedfolder
```

Теперь новые файлы внутри каталога будут получать группу `developers`:

```bash
touch mysharedfolder/example.txt
ls -l mysharedfolder/example.txt
```

> SGID обеспечивает наследование группы, но не гарантирует группе право записи в новые файлы. Итоговые права также зависят от `umask` пользователя и стандартных ACL.

Найти каталоги с SGID:

```bash
find / -type d -perm -2000 2>/dev/null
```

## Sticky bit

### Что делает Sticky bit

Sticky bit обычно устанавливается на общие каталоги, в которые могут записывать несколько пользователей.

Без Sticky bit пользователь с правом записи в каталог может удалять и переименовывать находящиеся в нём файлы, даже если эти файлы принадлежат другим пользователям.

При установленном Sticky bit удалить или переименовать файл внутри каталога могут:

- владелец файла;
- владелец каталога;
- пользователь `root`.

### Классический пример: `/tmp`

Каталог `/tmp` доступен для записи всем пользователям, но Sticky bit запрещает им удалять чужие файлы.

Проверка:

```bash
ls -ld /tmp
```

Обычно результат выглядит так:

```text
drwxrwxrwt ... /tmp
```

Буква `t` на месте права выполнения для остальных означает наличие Sticky bit:

```text
rwt
  ↑
Sticky bit
```

### Установка Sticky bit

Символический способ:

```bash
chmod +t shared_directory
```

Или более явно:

```bash
chmod o+t shared_directory
```

Числовой способ:

```bash
chmod 1777 shared_directory
```

Число `1` в старшем разряде обозначает Sticky bit:

```text
1777
│└── стандартные права rwxrwxrwx
└─── Sticky bit
```

Удаление Sticky bit:

```bash
chmod -t shared_directory
```

Найти каталоги со Sticky bit:

```bash
find / -type d -perm -1000 2>/dev/null
```

## Числовые обозначения специальных прав

Специальные биты записываются дополнительной цифрой перед обычными правами:

| Специальное право | Число | Пример |
|---|:---:|---|
| Sticky bit | `1` | `chmod 1777 directory` |
| SGID | `2` | `chmod 2775 directory` |
| SUID | `4` | `chmod 4755 file` |

Специальные биты можно комбинировать:

| Комбинация | Число |
|---|:---:|
| SUID + SGID | `6` |
| SUID + Sticky bit | `5` |
| SGID + Sticky bit | `3` |
| SUID + SGID + Sticky bit | `7` |

Например:

```bash
chmod 6755 file
```

Здесь:

```text
6 = 4 + 2 = SUID + SGID
```

## Обозначения в выводе `ls -l`

| Символ | Значение |
|:---:|---|
| `s` на месте `x` владельца | SUID установлен, выполнение разрешено |
| `S` на месте `x` владельца | SUID установлен, но выполнение не разрешено |
| `s` на месте `x` группы | SGID установлен, выполнение разрешено |
| `S` на месте `x` группы | SGID установлен, но выполнение не разрешено |
| `t` на месте `x` остальных | Sticky bit установлен, выполнение разрешено |
| `T` на месте `x` остальных | Sticky bit установлен, но выполнение не разрешено |

Примеры:

```text
-rwsr-xr-x  → SUID
-rwxr-sr-x  → SGID
drwxrwxrwt  → Sticky bit
```

## Краткая таблица

| Право | Для файлов | Для каталогов | Символическая команда | Числовой пример |
|---|---|---|---|---|
| SUID | Запуск с правами владельца | Обычно игнорируется в Linux | `chmod u+s file` | `chmod 4755 file` |
| SGID | Запуск с правами группы | Новые объекты наследуют группу каталога | `chmod g+s path` | `chmod 2775 directory` |
| Sticky bit | Практически не используется | Запрещает удалять чужие файлы в общем каталоге | `chmod +t directory` | `chmod 1777 directory` |

## Главное

```text
SUID       → выполнить от имени владельца файла
SGID-файл  → выполнить от имени группы файла
SGID-папка → наследовать группу каталога
Sticky bit → нельзя удалять чужие файлы из общего каталога
```
