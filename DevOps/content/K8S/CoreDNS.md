 # CoreDNS и Service Discovery в Kubernetes
**Теги:** #kubernetes #dns #networking 

## Что такое CoreDNS
**CoreDNS** - системный DNS-сервер , обеспечивающий Service Discovery (обнаружение сервисов). 
Позволяет Pod'ам находить друг друга по доменным именам, а не по нестабильным IP-адресам.

**Стандарт формирования внутреннего адреса (FQDN):**
`<имя-сервиса>.<неймспейс>.svc.cluster.local`
* Пример внутри одного неймспейса: `http://db-service`
* Пример из другого неймспейса: `http://db-service.storage.svc.cluster.local`

*Примечание:* Для Headless Service (`clusterIP: None`) CoreDNS создает отдельные записи для каждого Pod'а (например, `redis-0.redis-service...`), что необходимо для кластерных баз данных (StatefulSet).

## Политики DNS (dnsPolicy)
Указываются в спецификации Pod'а и определяют, куда он будет отправлять DNS-запросы.

1. `ClusterFirst` **(По умолчанию)**
   * Все запросы идут в CoreDNS.
   * Внутрикластерные адреса резолвятся локально, внешние (например, `google.com`) форвардятся наружу.
2. `Default`
   * Название обманчиво (это не политика по умолчанию).
   * Pod берет настройки DNS из физической ноды (`/etc/resolv.conf`).
   * **Минус:** Pod не видит внутренние сервисы Кубернетеса.
3. `ClusterFirstWithHostNet`
   * Костыль для Pod'ов с `hostNetwork: true`.
   * Заставляет Pod в сети хоста всё равно использовать внутрикластерный CoreDNS для поиска соседних сервисов.
4. `None`
   * Полностью ручная настройка.
   * Требует обязательного добавления блока `dnsConfig` в манифест с явным указанием нужных DNS-серверов (например, `8.8.8.8`).
